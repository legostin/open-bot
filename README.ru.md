# Owlbot

[English](README.md)

Дружелюбный и проактивный персональный агент, который живёт у вас. Это open-source альтернатива Grok, Meta Muse и OpenAI Dots: установщик для вашего компьютера или один Docker-образ для сервера, ваши подписки, ваши компьютеры и безопасность с первого дня. Говорит по-русски и по-английски.

## Возможности

- **Ваши подписки как «мозги».** Claude Code (подписка Claude) и Codex (подписка ChatGPT) работают как харнессы, а API Anthropic, OpenAI, OpenRouter и любой OpenAI-совместимый сервер — как запасной вариант. Когда упираетесь в лимит подписки, агент сам переключается на следующий мозг и возвращается, когда лимит сбросится.
- **Проактивность.** Напоминания, расписания и мониторинг страниц и лент. Фоновые задачи сами решают, стоит ли вас беспокоить: молча, в дайджест, уведомление или вопрос.
- **Агент — входная точка.** Говорите агенту, что нужно, хоть несколько дел сразу или ещё по ходу работы: быстрое он делает сам, а всё, где есть шаги, отдаёт задачам, которые идут в стороне. Он сам выбирает, кто из команды и на каком компьютере будет работать, и спрашивает вас, только если выбор неочевиден. Вы видите по строке на задачу и получаете результаты. Задача может спросить агента, который её поставил, а агент может дослать ей подробности на ходу: они попадают в работу на ближайшем шаге у любого мозга (Claude Code, Codex, API).
- **Несколько агентов и групповые чаты.** Задачи можно делегировать и выполнять параллельно. Нескольких агентов можно собрать в один чат: они видят реплики друг друга, отвечают по упоминанию `@имя` и передают друг другу слово. Агенты описываются markdown-файлами, у каждого свой список мозгов и инструментов.
- **Живой чат.** Ответы с разметкой (заголовки, списки, таблицы, код) — и в веб-интерфейсе, и в Telegram. Агент может показать картинку, карусель фотографий или карту OpenStreetMap прямо в сообщении. Ему можно так же отправлять файлы, фото и скриншоты: скрепкой, вставкой или перетаскиванием в веб-интерфейсе или просто в Telegram, где работают ещё голосовые, альбомы и места на карте. Голосовые расшифровываются до ответа агента: с ключом Groq (есть бесплатный тариф), OpenAI или через свой сервер Whisper (**Настройки → Голосовые сообщения**). С первым голосовым ассистент сам предложит это настроить. Формы в чате после сохранения сворачиваются в одну строку и не мешают дальше.
- **Память.** Долговременная память о вас: markdown-факты с историей в git и полнотекстовым поиском. Факты из недоверенных сессий ждут вашей проверки.
- **MCP и скиллы.** Подключаются любые MCP-серверы, скиллы и команды. Плагины Claude Code и Codex ставятся как есть.
- **Встроенный браузер.** Chromium внутри контейнера (вне Docker он ставится сам при первом использовании): сайты, формы, скриншоты, вход по паролям из vault и живой экран, на котором можно перехватить управление.
- **Сеть машин.** Другие компьютеры подключаются как узлы. Агент запускает на них команды, работает с файлами и использует их подписки (Claude Code или Codex на ноутбуке).
- **Безопасность.** Vault для паролей и личных данных: модель видит только ссылки `vault://`. Внешние действия требуют подтверждения в отдельном пульте. Плагины и CLI-мозги работают в песочнице под отдельными unix-пользователями, весь их трафик идёт через egress-фильтр. Журнал аудита защищён цепочкой хэшей.
- **Всё — плагины, включая интерфейс.** Панели, вкладки, рендер результатов, композер, каналы, мозги, инструменты. Подробности — в [docs/plugins.ru.md](docs/plugins.ru.md).
- **Каналы.** Приложение для Windows и macOS, приложение для iPhone (см. [Телефон](#телефон)), веб-интерфейс и Telegram.
- **Доступ из любого места.** Одна постоянная ссылка на хаб для любого браузера и приложения на телефоне через собственный узел Tailscale в Owlbot: на телефон ничего ставить не нужно, порты открывать тоже (см. [Доступ из любого места](#доступ-из-любого-места)).

## Быстрый старт

### На вашем компьютере (Windows, macOS)

Возьмите приложение: `owlbot-setup-<version>-x64.exe` для Windows 10 и 11, `owlbot-<version>.dmg` для macOS 13.5 и новее (Apple silicon и Intel). В нём есть всё нужное: Node.js, Docker и WSL не понадобятся. Как собрать его самому, описано в разделе [Приложение для компьютера](#приложение-для-компьютера).

1. В Windows запустите установщик: он ставит Owlbot только для вашего пользователя и не просит прав администратора. В macOS откройте образ диска, перетащите Owlbot в «Программы» и откройте его оттуда.
2. Приложение спросит, как вы будете пользоваться этим компьютером:
   - **Новый Owlbot на этом компьютере**: хаб запустится здесь и откроется в окне приложения. Придумайте пароль, и всё готово (код установки копировать не нужно). Дальше приложение входит в своё окно само.
   - **Подключить к моему Owlbot**: ваш хаб работает в другом месте, а этот компьютер станет одной из его машин. Вставьте адрес хаба и код со страницы **Машины** или нажмите там **Подключить через приложение**. Окно покажет тот хаб.
3. Если закрыть окно, Owlbot продолжит работать в фоне (Telegram, задачи, напоминания); у его значка в строке меню или трее есть пункты «Открыть», «Запускать при входе в систему», «Показать журнал», «Перезапустить», «Настроить заново…», «Сбросить Owlbot…» и «Выйти». При входе в систему он запускается сам.

Claude Code и Codex: если один из них уже установлен на компьютере и вы в него вошли, Owlbot возьмёт его вместе со входом — входить второй раз не нужно. Если нет, кнопка **Войти** на его карточке установит его для Owlbot (разовая загрузка на несколько сотен МБ), а потом начнётся вход.

Чтобы начать с чистого листа, выберите в меню значка **Сбросить Owlbot…**. Приложение покажет, что удалится: чаты, агенты, память, хранилище с секретами, плагины, настройки, подключение компьютера к хабу и автозапуск. После подтверждения оно удалит всё это и либо снова предложит первую настройку, либо закроется. Входы в Claude Code и Codex останутся: они принадлежат этим программам, а не Owlbot.

Данные лежат в `%LOCALAPPDATA%\Owlbot` (Windows) или `~/Library/Application Support/Owlbot` (macOS); обновление их сохраняет. Чтобы обновить Owlbot в macOS, перетащите новую версию в «Программы» и замените старую. Удалить Owlbot можно в **Параметры → Приложения** в Windows (он спросит, удалять ли ваши данные) или перетащив Owlbot из «Программ» в Корзину в macOS (данные останутся; чтобы удалить и их, сначала выберите в меню значка **Сбросить Owlbot… → Удалить и выйти**). Хаб слушает `http://localhost:41780` (пульт — `:41781`, egress-прокси — `:41789`), в стороне от портов, которые часто заняты другими программами (8080, 18789 у OpenClaw); другой порт задаётся в `desktop.json` в папке данных как `{"port": 19000}`. Он доступен только с этого компьютера; как подключить телефон, описано в разделе [Телефон](#телефон).

На компьютере хаб, плагины и CLI-мозги работают от вашего пользователя: отдельных Unix-пользователей и блокировки сети на уровне ядра, как в Docker-образе, здесь нет. Для самой строгой изоляции запускайте Owlbot в Docker.

Приложение пока не подписано. Windows SmartScreen может написать «Система Windows защитила ваш компьютер»: нажмите **Подробнее → Выполнить в любом случае**. Если macOS не открывает приложение, нажмите **Все равно открыть** в **Системные настройки → Конфиденциальность и безопасность** (в macOS 13 и 14 можно и щёлкнуть приложение с Control и выбрать **Открыть**).

### На сервере (Docker)

```bash
git clone <repo> owlbot && cd owlbot
docker compose up -d --build
docker compose logs owlbot | grep -A1 "Owlbot:"
```

1. Откройте http://localhost:8080, введите **код установки** из логов и придумайте пароль. Язык вашего браузера станет языком хаба (см. [Языки](#языки)).
2. Пока не работает ни один мозг, чат показывает карточку настройки: войдите в Claude Code или Codex по своей подписке (в установке на компьютер хаб сначала сам поставит недостающий CLI) или дайте API-ключ (см. ниже). На всё, что вы напишете в это время, ассистент ответит, как только мозг подключится.
3. Дальше настройку в чате ведёт ассистент, по одному шагу и только с вашего согласия: Telegram, запасной мозг, другие компьютеры и знакомство с вами. «Не сейчас» пропускает шаг, «продолжим настройку» возвращает к нему. Когда для чего-то нужен ключ или токен, ассистент покажет в чате защищённое поле: значение сразу уходит в зашифрованное хранилище, а модель видит только `vault://id`. Можно и просто вставить токен в сообщение: хаб узнаёт известные форматы, вырезает токен из сообщения и сохраняет его.

Данные лежат в томе `owlbot-data` (`/data`): база, vault, рабочие папки, логины CLI, плагины.

## Языки

- **Язык хаба** берётся из браузера первого пользователя при установке. Его можно закрепить переменной `OWLBOT_LANG=en` или `OWLBOT_LANG=ru`, а позже поменять в «Настройках». На нём приходят уведомления, сообщения в Telegram и карточки подтверждения, и он же — язык интерфейса по умолчанию.
- В каждом браузере язык интерфейса можно переключить отдельно; язык хаба от этого не меняется.
- Агенты отвечают на том языке, на котором вы им пишете.

## Подключение мозгов

**Claude Code (подписка Claude Pro/Max) и Codex (подписка ChatGPT)** входят прямо из чата. Нажмите **«Войти»** рядом с мозгом в карточке настройки или попросите ассистента («подключи Codex»): карточка покажет страницу входа, которую нужно открыть.

- **Codex:** введите на этой странице одноразовый код из карточки.
- **Claude Code:** войдите, скопируйте код, который покажет страница, и вставьте его в карточку (не в чат).

Когда мозг авторизуется, карточка станет зелёной. Логин хранится на сервере в `/data/home/agent`, так что в терминале ничего запускать не нужно. На странице «Мозги» есть те же кнопки.

Вместо этого Claude Code может работать по долгоживущему токену: выполните `claude setup-token` на любом компьютере с Claude Code и вставьте токен в чат. Он сохранится в хранилище как **`claude_code_token`**, и мозг Claude Code его подхватит.

**API-ключи** (запасные мозги, веб-поиск): попросите ассистента («подключи поиск Brave») или вставьте ключ в чат. В хранилище они лежат под такими id:

| id | Для чего |
|---|---|
| `anthropic_api_key` | мозг `api:anthropic` |
| `openai_api_key` | мозг `api:openai`, Codex по ключу |
| `openrouter_api_key` | мозг `api:openrouter` |
| `custom_llm_api_key` | мозг `api:custom` (Ollama, LM Studio, vLLM или другой OpenAI-совместимый сервер), только если серверу нужен ключ |
| `brave_api_key` или `tavily_api_key` | `web_search`; без ключа укажите свой SearXNG в настройках плагина «Веб» (DuckDuckGo часто отвечает проверкой на бота) |
| `telegram_bot_token` | канал Telegram |

Адрес и модель OpenAI-совместимого сервера задаются в настройках плагина API-мозга. Сервер в локальной сети нужно ещё добавить в настройку `brainEgressAllow` (localhost доступен всегда).

Состояние мозгов (установлен, вошёл, лимит до …) видно на странице «Мозги». Порядок мозгов задаётся у каждого агента.

## Групповые чаты

Нескольких агентов можно позвать в один чат: в боковой панели в разделе **Группы** нажмите **Новая группа**, дайте ей название и выберите от двух до восьми агентов. Первый выбранный — ведущий.

- Сообщение без упоминания получает ведущий.
- `@имя` зовёт конкретного агента: наберите `@`, и чат подскажет участников.
- `@все` — ответят все по очереди, и каждый видит, что уже сказали до него.
- Агент может сам передать слово другому, упомянув его в ответе (не больше трёх передач на одно ваше сообщение).

Название и состав группы меняются по кнопке рядом с её названием. Групповые чаты живут в приложении и веб-интерфейсе, в Telegram они не дублируются.

## Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather) и попросите ассистента подключить Telegram: токен вводится в его карточку. Бот подключится сам.
2. В той же карточке нажмите **«Открыть бота в Telegram»** и затем «Старт»: так чат привяжется. Бот отвечает только тому личному чату, из которого его привязали.

В Telegram приходят ответы (с разметкой: жирный текст, списки, код, таблицы), уведомления, дайджест и карточки подтверждения с кнопками. Картинки из ответа приходят фотографиями или альбомом, карта — точкой на карте. Боту можно отправлять фото, альбомы, файлы и голосовые до 20 МБ (ограничение Telegram для ботов) или место на карте: агент получит их в своей рабочей папке. По пересланному сообщению или ответу на сообщение агент понимает, откуда оно и на что вы отвечаете. Команды в чате: `/help`, `/tasks`, `/stop`. Подробности действия видны только в пульте, если не включить настройку `channelApprovalDetails`.

## Интеграции

**Настройки → Интеграции** — это сервисы, с которыми работают ваши агенты, в виде карточек: пока доступ из любого места, Google Календарь, Telegram, поиск в интернете и браузер. Карточка показывает состояние и одну кнопку, которая продвигает дело. Можно и просто попросить ассистента («подключи мой Google Календарь»): он покажет ту же карточку в чате.

**Google Календарь.** Нажмите **Войти через Google**, выберите аккаунт и разрешите доступ. Google вернёт браузер в хаб. Если хаб работает на сервере или вы входите с телефона, страница возврата не откроется: скопируйте её адрес из строки браузера в карточку. Вход хранится в хранилище, поэтому сначала создайте или откройте его (карточка это предложит). После этого агенты видят ваши события и свободное время, могут создавать, переносить и удалять события (каждое изменение — с вашего подтверждения), а утренняя сводка показывает план дня, вечерняя — на завтра.

Owlbot входит в Google через свой клиент. Чтобы использовать свой, создайте его в [Google Cloud](https://console.cloud.google.com/): проект с включённым Google Calendar API, экран согласия OAuth (External, In production) и OAuth-клиент типа **Desktop app**. Затем задайте `OWLBOT_GOOGLE_CLIENT_ID` и `OWLBOT_GOOGLE_CLIENT_SECRET`. Пока Google не проверил доступ клиента к календарю, при входе будет предупреждение «непроверенное приложение».

## Другие компьютеры

1. На странице «Машины» нажмите «Подключить машину» и получите одноразовый код (действует 10 минут).
2. На другом компьютере (нужен только Node.js 24.5+) скачайте демон с хаба и привяжите машину; `<code>` — полученный код:
   ```bash
   curl -fsSLo owlbot-node.mjs https://your-hub-url/download/owlbot-node.mjs
   node owlbot-node.mjs pair https://your-hub-url <code> --name laptop
   node owlbot-node.mjs run
   ```
3. Узел появится в списке. Его локальные Claude Code и Codex станут мозгами `claude-code@<машина>` и `codex@<машина>`. Что агенту можно делать на машине (папки, команды, мозги), решает владелец машины в `~/.owlbot-node/policy.json`. По умолчанию команды выключены. Автозапуск через systemd, launchd и Планировщик заданий описан в [packages/node/README.ru.md](packages/node/README.ru.md).

Под командой в боковой панели (и на вкладке **Хаб** в приложении для телефона) у каждой машины видно, в сети ли она, а пока там работают агенты — кто над чем работает и что делает прямо сейчас: запускает команду, читает или правит файлы, ищет в интернете, пишет ответ или ждёт вашего решения. Строка открывает этот чат или задачу.

## Телефон

iOS-приложение Owlbot (репозиторий `owlbot-ios`) — хаб в кармане: команда агентов, чаты со всеми карточками, задачи, уведомления и подтверждения по Face ID. На телефоне нет мозгов: он подключается к этому хабу.

1. В **Настройки → Устройства** нажмите **«Подключить телефон»** и отсканируйте QR приложением или откройте ссылку на телефоне. Можно и попросить ассистента «подключи мой телефон» или выполнить на сервере `owlbot devices pair` — QR появится в терминале.
2. Подтвердите на телефоне через Face ID.

QR даёт телефону все адреса, по которым тот может достучаться, и телефон берёт тот, что ответит: отдельный HTTPS-порт хаба для телефонов в домашней сети (порт хаба + 2: 41782 в десктоп-приложении, 8082 на сервере; `OWLBOT_DEVICE_PORT`; в сеть открывается только он, веб остаётся где был), адрес компьютера в Tailscale и ссылку из [доступа из любого места](#доступ-из-любого-места) (телефон, привязанный раньше, узнаёт её при следующем подключении). `OWLBOT_DEVICES=0` закрывает порт в домашней сети, и тогда телефоны ходят только по ссылке. Телефон пинит собственный сертификат хаба из QR, поэтому домен и CA не нужны. Токен телефона отзывается в один клик в «Устройствах»; чтобы разрешить действие, нужна подпись ключом, который не покидает Secure Enclave телефона, так что украденный токен ничего не разрешит. Правила, записи vault и аудит остаются на пульте. В Docker опубликуйте порт для телефонов и укажите адреса, по которым их искать: `OWLBOT_DEVICE_URLS=https://192.168.1.10:8082`.

## Доступ из любого места

**Настройки → Интеграции → Доступ из любого места** даёт хабу одну постоянную ссылку `https://owlbot.<ваша-сеть>.ts.net`. Она открывает веб-интерфейс в любом браузере и обслуживает приложение на телефоне вне дома; на телефон и другой компьютер ничего ставить не нужно. Owlbot запускает собственный узел [Tailscale](https://tailscale.com) (`packages/tailnet`) и открывает ссылку через Tailscale Funnel.

1. Нажмите **«Включить»**.
2. **Войдите в Tailscale**: хватит бесплатного аккаунта (Google, Apple, GitHub или Microsoft). Узел `owlbot` появится в вашей сети.
3. **Разрешите Funnel**: Tailscale один раз спросит администратора сети.

По ссылке доступны веб-интерфейс (вход по паролю Owlbot: passkey привязаны к адресу самого компьютера), приложение на телефоне и другие машины (`owlbot-node pair <ссылка> <код>`). Никогда не доступны: первая настройка, консоль безопасности и вебхуки плагинов; мозги на машинах, привязанных по ссылке, обращаются к инструментам хаба через неё со своими токенами сессий. Неверные пароли считаются по адресам, а для ссылки ещё и вместе: 30 за час приостанавливают вход извне на час и присылают вам уведомление, вход на самом компьютере продолжает работать. Ключи узла лежат в `<data>/tailnet`; **«Забыть узел»** выходит из Tailscale и удаляет их. По умолчанию Tailscale просит узел войти заново через 180 дней: карточка предупредит за две недели, а в консоли администратора Tailscale можно отключить срок ключа для `owlbot`. Логи узла Owlbot в Tailscale не отправляет.

Узел входит в приложение для компьютера и в Docker-образ. При запуске из исходников соберите его командой `npm run build:tailnet` (нужен Go); без него карточка скажет, что доступ недоступен.

### Свой Tailscale или прокси

Не публикуйте порты в интернет напрямую. Чтобы извне была доступна и консоль безопасности, поставьте [Tailscale](https://tailscale.com) на хост и откройте оба порта через `tailscale serve` с HTTPS (в tailnet должны быть включены HTTPS-сертификаты):

```bash
tailscale serve --bg --https=8080 http://127.0.0.1:8080
tailscale serve --bg --https=8081 http://127.0.0.1:8081
```

Затем укажите адреса хаба:

```yaml
environment:
  OWLBOT_PUBLIC_URL: https://my-box.tailnet.ts.net:8080
  OWLBOT_CONSOLE_URL: https://my-box.tailnet.ts.net:8081
```

Для passkeys (вход без пароля) нужен HTTPS или `localhost`. `tailscale serve` получает сертификат автоматически.

## Модель безопасности

- **Два origin.** Чат и плагины работают на `:8080`. Подтверждения, vault, правила и аудит — на `:8081`, с отдельной cookie, строгим CSP и `frame-ancestors 'none'`. Код плагинов в основной странице не может прочитать или нажать то, что в пульте.
- **Vault.** Секреты шифруются: XChaCha20-Poly1305 с ключом данных, обёрнутым ключом из Argon2id. Модели видят только `vault://id`. Плагин получает запись, только если она объявлена в его правах **и** её область разрешает этот плагин, домен или агента. Значения секретов вырезаются из всего, что уходит модели, в каналы и в логи. После перезапуска vault запечатан, если при создании не отмечено «открывать автоматически» (тогда парольная фраза хранится в `/data/vault.passphrase`, её может прочитать только хаб) и не передан файл с паролем через `OWLBOT_VAULT_PASSPHRASE_FILE` (docker secret).
- **Политика инструментов.** У каждого инструмента есть эффект: `read`, `local-write` или `external`. Внешние действия по умолчанию требуют подтверждения. «Всегда разрешать» создаёт узкое правило (получатель, домен). Если сессия читала недоверенный контент (веб, почта), новые адресаты снова требуют подтверждения. Фоновые задачи агентов с инициативой ниже 2 могут только читать и уведомлять.
- **Песочница.** Хаб работает от пользователя `owlbot`, CLI-мозги — от `agent`, остальные плагины и MCP-серверы — от `plugin`. Трафик идёт через egress-прокси с белыми списками. С `cap_add: [NET_ADMIN]` и `OWLBOT_EGRESS_ENFORCED=iptables` прямой выход в сеть для `agent` и `plugin` закрыт на уровне ядра.
- **Узлы.** Узлы аутентифицируются ключом Ed25519, полученным при одноразовом спаривании. Каждое действие на машине проходит политику хаба и локальную политику узла.
- **Аудит.** Все вызовы инструментов, решения политики, доступ к vault и входы записываются в журнал с цепочкой хэшей. Проверить целостность можно командой `docker exec owlbot owlbot-entrypoint audit-verify` или в пульте.

## Команды контейнера

```bash
docker exec owlbot owlbot-entrypoint reset-password 'new-password'
docker exec owlbot owlbot-entrypoint pairing-code laptop
docker exec owlbot owlbot-entrypoint backup /data/backups
docker exec owlbot owlbot-entrypoint audit-verify
```

- `reset-password` задаёт новый пароль (не короче 8 символов) и завершает все сессии.
- `pairing-code [имя]` выдаёт одноразовый код для подключения машины.
- `backup [папка]` копирует базы, агентов, скиллы, команды и плагины с их данными; vault остаётся зашифрованным.
- `audit-verify` проверяет цепочку хэшей журнала аудита и завершается с кодом 2, если она нарушена.

## Переменные окружения

| Переменная | По умолчанию | |
|---|---|---|
| `OWLBOT_PUBLIC_URL` | `http://localhost:8080` | адрес чата, нужен для ссылок и проверки Origin |
| `OWLBOT_CONSOLE_URL` | тот же хост, порт 8081 | адрес пульта |
| `OWLBOT_ALLOWED_HOSTS` | — | дополнительные имена хоста через запятую |
| `OWLBOT_LANG` | — | закрепить язык хаба: `en` или `ru` |
| `OWLBOT_VAULT_PASSPHRASE_FILE` | — | автоматическая разблокировка vault |
| `OWLBOT_EGRESS_ENFORCED` | `proxy` | `iptables` — жёсткий запрет прямого выхода (нужен `NET_ADMIN`) |
| `OWLBOT_SETUP_TOKEN` | случайный | задать код установки заранее |
| `OWLBOT_TRUST_PROXY` | — | `1` — доверять `X-Forwarded-*` от обратного прокси |
| `OWLBOT_HOST` | `127.0.0.1` (в образе `0.0.0.0`) | адрес, на котором слушает хаб |
| `OWLBOT_PORT`, `OWLBOT_CONSOLE_PORT`, `OWLBOT_EGRESS_PORT` | `8080`, `8081`, `8089` | порты чата, пульта и egress-прокси |
| `OWLBOT_DEVICE_PORT`, `OWLBOT_DEVICE_HOST` | порт + 2 (`8082`), `0.0.0.0` | HTTPS-порт для телефонов и адрес, на котором он слушает |
| `OWLBOT_DEVICES` | — | `0` закрывает порт для телефонов в сети: тогда телефоны ходят к хабу только по ссылке |
| `OWLBOT_DEVICE_URLS` | определяются сами | адреса для QR привязки через запятую, раньше найденных автоматически |
| `OWLBOT_DATA_DIR` | `.data/` (в образе `/data`) | папка с данными |
| `OWLBOT_INSTALL_CLIS` | — (`1` в установщиках для компьютера) | `1` разрешает кнопке **Войти** установить недостающий Claude Code или Codex в `<data>/tools` |
| `OWLBOT_GOOGLE_CLIENT_ID`, `OWLBOT_GOOGLE_CLIENT_SECRET` | клиент Owlbot | свой OAuth-клиент Google (тип Desktop app) для интеграций Google |
| `OWLBOT_TAILNET_BIN` | `packages/tailnet/bin/<платформа>-<архитектура>/owlbot-tailnet` | узел Tailscale хаба для доступа из любого места |
| `OWLBOT_TAILNET_HOSTNAME` | `owlbot` | имя узла в вашей сети: первая часть ссылки |
| `TZ` | часовой пояс системы (в образе `UTC`) | часовой пояс по умолчанию для напоминаний, тихих часов и дайджеста |

Большая часть поведения настраивается в «Настройках» веб-интерфейса: язык, часовой пояс, тихие часы, время дайджеста, `channelApprovalDetails` (подробности действия в Telegram) и `brainEgressAllow` (дополнительные хосты для мозгов). Для одной настройки хаба на этой странице пока нет поля: `egressPrivateAllow` — хосты локальной сети, к которым можно плагинам и мозгам (например, `searxng` или `nas.local`); её меняют через `PATCH /api/settings`.

## Разработка

```bash
npm install
npm run build        # web UI, console, UI plugins, node daemon bundle
npm run build:tailnet  # the hub's Tailscale node (Go; --all for every platform)
npm run dev          # hub on :8080 / :8081, egress proxy on :8089 (data in .data/)
npm test             # unit and integration tests
npm run typecheck
```

Нужен Node.js 24.5+ (TypeScript запускается без сборки). Вне Docker плагин браузера сам скачивает Chromium для Playwright, если при старте его нет (один раз, в кэш Playwright или в `PLAYWRIGHT_BROWSERS_PATH`); браузерные вызовы на это время ждут загрузки. Чтобы отключить это и поставить браузер самому (`npx playwright install chromium`), задайте `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1`. Устройство проекта и соглашения описаны в [CLAUDE.md](CLAUDE.md), дизайн — в [docs/superpowers/specs](docs/superpowers/specs/2026-10-26-open-bot-design.md). Сообщения ядра лежат в `packages/core/src/locales/{en,ru}.ts`, сообщения плагинов — в `.owlbot-plugin/locales/{en,ru}.json`; `npm test` проверяет, что каждый перевод совпадает с английским.

### Приложение для компьютера

```bash
npm run package:desktop   # в Windows: dist/desktop/owlbot-setup-<version>-x64.exe
                          # в macOS:   dist/desktop/owlbot-<version>.dmg и .pkg
```

Приложение лежит в `packages/desktop` (Tauri 2: Rust в `src-tauri`, его экраны настройки в `ui`). Сборка собирает интерфейсы, складывает хаб с production-зависимостями и официальной сборкой Node 24, сверенной с SHA-256 из релиза (`packaging/desktop/stage.mjs`; другой релиз задаёт `NODE_VERSION`), и упаковывает его в приложение. Нужен Rust из [rustup](https://rustup.rs); в macOS ещё цель Intel для универсальной сборки (`rustup target add x86_64-apple-darwin`) и инструменты командной строки Xcode. Тексты приложения и установщиков лежат в `packaging/desktop/locales/{en,ru}.json`.

Тихая установка: `owlbot-setup-<version>-x64.exe /S` (с `/NOSTART` приложение не запустится) в Windows; `sudo installer -pkg owlbot-<version>.pkg -target /` в macOS (по SSH или через MDM), а `sudo /Applications/Owlbot.app/Contents/Resources/uninstall.sh <uid> <home> [--delete-data]` удаляет его. `Owlbot --mode hub --background` делает выбор первого запуска без окна, `Owlbot --quit` останавливает работающее приложение. `.github/workflows/desktop.yml` собирает обе версии на чистых машинах и проверяет, что они ставятся, запускают хаб, выходят и удаляются.

Чтобы попробовать сборку рядом с установленным Owlbot, добавьте `-- --test`: получится **Owlbot Test** (`owlbot-test-<version>.dmg`, `owlbot-test-setup-<version>-x64.exe`) со своими данными, подключением машины, автозапуском и портами сразу за основными (41790, пульт — 41791, egress-прокси — 41799). В заголовке окна, меню в трее и на экранах настройки видно, что это тестовая сборка.

Чтобы запустить приложение из исходников, не трогая установленный Owlbot: один раз подготовьте сборку (`node packaging/desktop/stage.mjs --skip-build`), затем `OWLBOT_APP_ROOT=$PWD/dist/desktop/stage-darwin/app OWLBOT_DATA_DIR=/tmp/owl-data npm run tauri -w @owlbot/desktop -- dev`, а в `/tmp/owl-data/desktop.json` положите `{"port":18080}`. С заданным `OWLBOT_DATA_DIR` приложение не прописывает себя в автозапуск.
